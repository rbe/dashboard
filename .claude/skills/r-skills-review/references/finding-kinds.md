# Finding kinds

## Same rule in two places

- Two places state one obligation: the same actor, the same condition, and the same result.
- Different words for the same obligation count. Compare the meaning, not the text.
- A place that adds a number, a name, or a condition that the other lacks is not a repeat. Only the repeated part is the finding.
- A sentence in a skill that restates a general rule or a line of the communication contract is a repeat, because the general rules apply to every skill.

## Same action in two skills

- Two skills each tell the agent to do the same thing at the same point: write the same file, run the same target, or ask the same question.
- A stage that calls a skill by name is not a second action. The skill that is called does the action.
- Two skills that check the same fact in the same stage are a finding.

## Contradiction

- Two places state unequal or opposite facts about one thing. A number, a list, or a scope that differs counts.
- A contradiction is not a repeat. The owner rule does not remove it. One side must change.
- Read the general rules and the code of the skill, such as its scripts and makefiles. Name the side that holds and the evidence as `path:line`.
- If nothing decides, the finding is a question with the choices.

## Not a finding

- A pointer to another skill or to a reference file.
- Two statements for two actors, two repository kinds, or two stages.
- A list of skill names in `CLAUDE.md`, its template, or the README. Each lists names and states no rule.
